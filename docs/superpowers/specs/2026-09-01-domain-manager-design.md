# DOMAIN. 本地域名收藏管理工具设计规范

- 日期：2026-09-01
- 状态：设计章节已确认，等待书面规范最终审阅
- 目标平台：macOS、Windows
- 工作名称：DOMAIN.

## 1. 产品概述

DOMAIN. 是一款离线优先的双平台桌面工具，用于集中管理常用网站、域名与网址。用户可维护网站名称、域名、完整网址、备注、自定义分类和多个标签，并通过搜索、组合筛选、排序、收藏置顶和批量操作整理收藏库。

应用全部核心数据保存在本机 SQLite 数据库。除打开网站和执行可用性检测外，应用不依赖远程服务，也不上传遥测或用户数据。

### 1.1 核心能力

1. 网站、分类和标签的增删改查。
2. 按关键词、分类、标签和状态组合筛选。
3. 按名称、域名、创建时间、更新时间和状态排序。
4. 收藏置顶、批量打标、批量移动分类、批量检测和批量删除。
5. 使用系统默认浏览器打开 HTTP 或 HTTPS 网址。
6. 手动及定时检测网站可用性，支持人工覆盖检测状态。
7. JSON、CSV 批量导入导出。
8. 手动完整备份、自动滚动快照与安全恢复。
9. 关闭主窗口后驻留系统托盘，并在应用进程运行期间执行计划检测。
10. 使用 vgpu 提供低强度 WebGPU 视觉效果，并提供无 WebGPU 降级。

### 1.2 明确不做

- 不提供账户、云同步、团队协作或远程数据库。
- 不在应用完全退出后执行后台检测。
- 不内嵌网页浏览器；网址始终交给系统默认浏览器。
- 首版不加密数据库或备份文件。
- 首版不保存完整的历次检测历史，只保存最新结果和连续失败计数。
- 首版不从远程服务抓取 favicon；列表图标使用本地生成的字母图标。
- 代码签名、公证证书和应用商店上架不属于首版实现范围，但构建配置应允许后续接入。

## 3. 技术路线

### 3.1 选定方案

采用 Tauri 2 + React/TypeScript + SQLite：

- React 负责桌面界面、交互状态和领域用例编排。
- TypeScript 领域层负责纯业务规则、输入规范化、查询条件和导入转换。
- Tauri/Rust 负责数据库、网络检测、文件、托盘、窗口生命周期和系统浏览器调用。
- SQLite 负责持久化、事务、组合查询和备份快照。
- vgpu 在独立 Canvas 中绘制装饰性效果，与业务 DOM 解耦。

### 3.2 未选方案

- Electron：WebGPU 环境更统一，开发也可保持全 TypeScript，但安装体积和后台资源占用更高。
- PWA/本地网页：无法可靠满足托盘驻留、原生文件恢复和应用运行时调度需求。

## 4. 架构与模块边界

系统分为四层，依赖方向自上而下。

### 4.1 React 界面层

- `workspace`：侧栏、统计摘要、搜索筛选、网站列表和批量工具条。
- `site-editor`：新增与编辑网站的右侧抽屉。
- `taxonomy`：分类和标签管理。
- `health`：检测进度、单项检测、批量检测和人工覆盖。
- `transfer`：JSON/CSV 导入、映射、预览、冲突处理和导出。
- `backup`：手动备份、自动快照列表和恢复向导。
- `settings`：检测周期、超时、并发、默认排序、关闭窗口行为和动态效果。
- `ambient-visual`：vgpu 初始化、渲染、暂停和降级。

界面层不直接执行 SQL、任意文件读写或 Shell 命令。

### 4.2 TypeScript 应用与领域层

- 收藏库服务：网站、分类、标签、置顶、排序和批量操作用例。
- 查询模型：将关键词、分类、标签、状态与排序转换为类型化查询参数。
- 状态模型：计算人工覆盖与自动检测结果组合后的有效状态。
- 导入模型：解析结果标准化、字段映射、逐行校验和冲突策略。
- Tauri 桥接接口：定义前端可调用的类型化命令和订阅事件。

领域规则应尽量保持纯函数，以便不启动桌面壳即可测试。

### 4.3 Tauri/Rust 系统层

- `commands`：窄接口、类型化输入输出和统一错误映射。
- `db`：SQLite 连接、迁移、仓库、事务和快照。
- `health`：异步 HTTP 执行器、队列、并发限制、重试与断网保护。
- `scheduler`：应用存活期间的计划检测和系统唤醒后的重新计算。
- `backup`：备份清单、校验和、原子恢复和回滚。
- `desktop`：托盘、窗口显隐、文件对话框和系统浏览器。

前端仅获得完成产品功能所需的 Tauri capability 权限。

### 4.4 本地持久化层

- SQLite 主库：网站、分类、标签、设置与最新检测状态。
- 用户选择文件：JSON、CSV 和 `.domain-backup`。
- 应用缓存：临时导入文件和可重建资源，不进入核心备份。

## 6. 数据模型

所有标识符使用 UUID 文本。所有持久化和交换时间统一使用带毫秒的 UTC RFC 3339 文本，例如 `2026-09-01T06:30:00.000Z`；显示时再转换为本地时区。

### 6.1 `sites`

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `id` | TEXT PK | UUID |
| `name` | TEXT | 非空，去除首尾空白 |
| `domain` | TEXT | 非空，作为用户可编辑的展示域名 |
| `url` | TEXT | 非空，只允许 HTTP/HTTPS |
| `normalized_url` | TEXT | 用于重复判断和索引，不设唯一约束 |
| `url_revision` | INTEGER | 从 1 开始；规范化 URL 改变时递增，用于拒绝迟到检测结果 |
| `row_revision` | INTEGER | 从 1 开始；任何网站字段、关联或健康状态变化时递增，用于乐观并发控制 |
| `notes` | TEXT | 默认空字符串 |
| `category_id` | TEXT NULL | 删除分类时设为 NULL |
| `is_pinned` | INTEGER | 0/1 |
| `auto_status` | TEXT | `unchecked`、`available`、`unavailable` |
| `manual_status` | TEXT NULL | NULL、`available`、`unavailable` |
| `failure_streak` | INTEGER | 连续非永久失败次数 |
| `last_checked_at` | TEXT NULL | 最近自动或手动检测时间 |
| `last_success_at` | TEXT NULL | 最近一次可用响应时间，失败时保持不变 |
| `last_check_source` | TEXT NULL | `scheduled` 或 `manual` |
| `last_http_status` | INTEGER NULL | 最近 HTTP 响应码 |
| `last_response_ms` | INTEGER NULL | 最近响应耗时 |
| `last_check_error` | TEXT NULL | 稳定错误代码，不保存敏感正文 |
| `created_at` | TEXT | 创建时间 |
| `updated_at` | TEXT | 最近业务修改时间 |

`normalized_url` 用于提示和匹配重复项。同一域名的不同子域名、路径或查询参数可以分别收藏；用户也可以在导入时明确选择创建重复副本。
网站字段、分类/标签关联、置顶、人工覆盖或检测健康字段每次成功变更都递增 `row_revision`；只读查询不递增。业务编辑同时更新 `updated_at`，纯检测结果只更新检测时间和 revision，不改变业务更新时间。

### 6.2 `categories`

- `id`、`name`、`name_key`、`color`、`sort_index`、`created_at`、`updated_at`。
- `name_key` 使用 §12.4 的 Unicode 规范化规则并保持唯一；`name` 保存用户展示文本。
- 删除分类不会删除网站，相关网站转为未分类。

### 6.3 `tags` 与 `site_tags`

- `tags`：`id`、`name`、`name_key`、`color`、`sort_index`、时间字段。
- `site_tags`：`site_id`、`tag_id` 联合主键。
- 标签 `name_key` 保持唯一。
- 删除标签只解除关联。

### 6.4 `app_settings`

键值形式保存检测周期、超时、并发、默认排序、关闭窗口行为、动态效果和减少动态效果选项。值使用版本化 JSON，并在 Rust 边界校验。

### 6.5 `scheduler_state`

单行表保存 `last_scheduled_run_at`、`next_scheduled_run_at`、`paused`、`last_outcome` 和 `updated_at`。手动检测不修改这张表。调度器不能从网站的 `last_checked_at` 反推全局计划。

### 6.6 索引与搜索

- 为 `normalized_url`、`category_id`、`is_pinned`、`auto_status`、`manual_status` 和常用排序列建立索引。
- 关键词搜索覆盖名称、域名、网址、备注和标签名称。
- 采用参数化查询和转义后的子串搜索，以正确支持中文与部分字符串匹配。
- 分类、标签和状态之间使用 AND 组合；选择多个标签时默认要求条目同时拥有全部选中标签。
- 状态筛选和摘要统计使用 `effective_status`，而不是只看自动检测值。
- 搜索输入使用短防抖；10,000 条数据下目标反馈时间小于 100 ms。

## 7. 网址录入与规范化

1. 用户未填写协议时补全 `https://`。
2. 只接受解析成功的 `http:` 或 `https:` URL。
3. 拒绝包含 username 或 password 的 URL，避免把凭证写入数据库、导出文件或日志。
4. `domain` 默认从 URL hostname 生成，但此后允许独立编辑。
5. 保留完整路径、查询参数和片段作为打开目标。
6. `normalized_url` 使用同一个 Rust/TypeScript 兼容测试向量定义：scheme 与 hostname 转为小写，Unicode hostname 按 URL 标准序列化为 ASCII，移除 HTTP 的 80 和 HTTPS 的 443 默认端口；HTTP 与 HTTPS 保持不同。
7. 根路径统一序列化为 `/`，因此 `https://example.com` 与 `https://example.com/` 相同；非根路径的尾部斜杠保留并参与重复判断。
8. 路径大小写、百分号编码语义、查询参数顺序、查询值和片段不重排、不解码，均参与重复判断。
9. 保存前提示 `normalized_url` 重复，但不强制阻止。
10. 系统浏览器调用前再次解析并验证协议，避免导入数据绕过录入校验。

实现必须维护一组共享规范化测试向量，确保 Rust 保存、TypeScript 预览和导入冲突检测得出相同结果。

### 7.1 URL 变更与迟到结果

- 普通编辑中，如果新旧 `normalized_url` 不同，保存时递增 `url_revision`，并把 `auto_status` 重置为 `unchecked`、`manual_status` 清为 NULL、`failure_streak` 归零，所有最近检测/成功/响应/错误字段清为 NULL。界面在保存前明确提示状态将被重置。
- 只改变名称、展示域名、备注、分类、标签或 URL 的等价序列化形式时不递增 revision，也不重置状态。
- 每个检测请求在发出前捕获 `site_id`、`normalized_url`、`url_revision` 和 `row_revision`。结果提交使用原子 compare-and-swap 条件；任一值已变化时把结果记为 `stale_target` 并丢弃，不修改任何较新的网站、人工覆盖或健康字段；成功写入健康结果时递增 `row_revision`。
- 因此检测发出后发生的备注、分类/标签、人工覆盖、JSON/CSV 健康字段导入或其他检测写入都会使旧结果失效。该次网络结果不自动重试；后续手动或计划 run 使用新 revision 重新检测。
- JSON/CSV 的“更新现有”只能更新与导入行 `normalized_url` 相同的目标，因此不会借更新策略改变目标 URL。不同 URL 作为新增项处理；普通编辑是首版唯一改变现有网站 URL 的入口。

## 8. 有效状态模型

自动状态和人工决定分别存储：

```text
effective_status = manual_status ?? auto_status
```

- 设置人工覆盖不会停止后台检测。
- 后台检测继续更新 `auto_status` 和最近检测信息。
- 清除人工覆盖后，页面立即显示最新自动状态。
- `checking` 仅是界面瞬时状态，不持久化。
- “手动检测”是用户主动发起一次网络请求，仍更新自动状态，并将 `last_check_source` 写为 `manual`。
- “手动覆盖”只修改 `manual_status` 和业务 `updated_at`，不修改 `last_checked_at`、`last_check_source` 或自动检测字段。

### 8.1 检测状态转移

每次独立检测任务对每个网站只产生一个最终结果。所有结果都会更新 `last_checked_at` 和 `last_check_source`。

| 最终结果 | 原自动状态 | 原失败计数 | 新自动状态 | 新失败计数 | 元数据处理 |
| --- | --- | ---: | --- | ---: | --- |
| 可用响应 | 任意 | 任意 | `available` | 0 | 写响应码、耗时和 `last_success_at`，清除旧错误 |
| 最终 GET 为 404/410 | 任意 | 任意 | `unavailable` | 0 | 写响应码和耗时，错误为 `http_404`/`http_410`，保留旧 `last_success_at` |
| 其他失败，第 1 次 | `unchecked` | 0 | `unchecked` | 1 | 清空响应码，写耗时和稳定错误码，保留 `last_success_at` |
| 其他失败，第 1 次 | `available` | 0 | `available` | 1 | 清空响应码，写耗时和稳定错误码，保留 `last_success_at` |
| 其他失败，第 1 次 | `unavailable` | 0 | `unavailable` | 1 | 清空响应码，写耗时和稳定错误码，保留 `last_success_at` |
| 其他失败，第 2 次及以后 | 任意 | ≥1 | `unavailable` | 2（封顶） | 清空响应码，写耗时和最新稳定错误码，保留 `last_success_at` |

重试属于同一次检测，不会重复增加失败计数。任何成功都会清除旧错误、旧响应码歧义和连续失败状态，但不会修改 `manual_status`。

### 8.2 页面状态映射

- “当前可用”：`effective_status = available`。
- “失效”：`effective_status = unavailable`。
- “待检测”：`last_checked_at IS NULL`，不受人工覆盖影响。
- “需要处理”：没有人工覆盖，并且 `auto_status != available` 或 `failure_streak > 0`。
- 人工覆盖必须以独立标识显示，让用户能看出页面状态不是纯自动结果。

## 9. 网站可用性检测

### 9.1 请求策略

1. 优先发送 HEAD 请求。300-399 且带合法 HTTP/HTTPS `Location` 时最多跟随 5 次跳转；超过上限或指向非 HTTP(S) 协议时以 `redirect_limit` 或 `unsafe_redirect` 失败。
2. 服务端对 HEAD 返回 400、403、404 或 405 时，改用带 `Range: bytes=0-0` 的 GET 请求，收到响应头后立即丢弃响应体，避免不支持 HEAD 的站点被误判。
3. 默认单请求超时 10 秒，设置范围限制为 3 至 60 秒。
4. 默认并发 5，设置范围限制为 1 至 20。
5. 对超时、连接拒绝/重置、临时 DNS 错误或任意 5xx 最多重试一次，并使用短随机退避；URL 解析、TLS 证书/协议错误和 4xx 不重试。
6. 取消任务时不再发出新请求；已完成结果仍使用短事务写入。

同一次检测任务内的重试只产生一个最终结果，最多将该网站的 `failure_streak` 增加一次。
每一次重定向都重新验证目标 scheme，只允许 HTTP/HTTPS。HEAD 触发 GET 降级时，以最终 GET 结果判定；HEAD 的 404 本身不会直接写入状态。304 或没有 `Location` 的其他 3xx 表示目标已返回 HTTP 响应，记为可用并保留响应码。

### 9.2 判定规则

- 2xx 和最终有效 3xx：可用。
- 401、403、429：目标可达，记为可用并保留响应码。
- 最终请求的 404、410：永久失败，立即记为失效。
- 其他 4xx、5xx、DNS、连接、TLS 和超时：本次失败。
- 成功立即设为可用，并清零 `failure_streak`。
- 除 404/410 外，连续两次失败后才将自动状态改为失效。

界面显示最近响应码、耗时、检测时间和稳定错误类型。错误详情不包含响应正文、认证信息或完整网络堆栈。

### 9.3 全局断网保护

“检测全部”和计划检测在进入普通队列前执行独立样本门控：

1. 从 `auto_status = available AND failure_streak = 0 AND last_success_at IS NOT NULL` 的网站中按 `last_success_at DESC`、`id ASC` 选取最多 5 个不同 URL hostname。这里使用解析后的 URL hostname，不使用可编辑的展示 `domain`。
2. 样本并发执行，但结果先保存在内存，不写数据库，也不增加失败计数。
3. 如果系统报告网络接口离线，立即中止。
4. 如果正好取得 5 个样本，且全部出现 DNS、连接或超时等传输级失败、没有任何 HTTP 响应，则判定疑似本机断网；丢弃全部样本结果，不启动普通队列。
5. 如果任一样本获得 HTTP 响应，或可用样本少于 5 个，则门控通过；样本结果和其余结果随后按正常状态机分别提交。

单条或选中项检测不使用全局样本门控，只依赖连续失败保护。门控失败时：

- 停止剩余队列。
- 保留网站原有自动状态和失败计数。
- 显示“网络不可用，未更新结果”。
- 允许用户在恢复网络后重试。

样本门控结束前不会启动其他请求，因此不存在门控失败后仍向旧数据库提交的在途普通任务。门控通过后，取消检测仍遵守“已完成结果保留、未发出请求停止”的普通规则。

断网保护不得依赖固定第三方探测地址，以避免不必要的隐私泄漏。

### 9.4 调度与托盘

- 默认每 6 小时运行，可选 1、3、6、12、24 小时。
- 首次启用时设置 `next_scheduled_run_at = now + interval`。
- 一轮计划检测正常完成或被用户取消后，设置 `last_scheduled_run_at = started_at`，并以完成时间计算下一次到期时间。
- 因疑似断网而中止时不更新 `last_scheduled_run_at`，下一次重试时间为 `now + min(15 分钟, interval)`。
- 应用启动时若 `next_scheduled_run_at <= now`，只补执行一次。
- 系统休眠期间自然暂停；唤醒或检测到系统时钟变化后读取持久化状态重新计算，任何时刻最多运行一轮。
- 修改周期后以当前时间重新计算下一次到期时间。暂停不删除历史状态；恢复后从当前时间开始一个新周期，不立即补跑。
- 手动检测不改变计划检测的 `last_scheduled_run_at` 或 `next_scheduled_run_at`。
- 关闭主窗口默认隐藏到托盘，首次发生时明确提示。
- 托盘菜单提供显示窗口、检测全部、暂停/恢复计划检测和退出。
- 从托盘明确退出时停止调度、触发活动 HTTP 队列取消、等待网络任务和当前数据库事务结束，再关闭数据库和进程。

### 9.5 检测运行仲裁

- 进程级 `HealthRunCoordinator` 在任何时刻最多允许一个检测 run，run 具有唯一 ID、`scheduled`/`manual` 来源、目标集合和取消令牌。
- 任意手动检测开始后，全部检测按钮和其他检测命令进入“已有检测运行中”状态；新的手动请求不排队、不重叠写入，用户可观察或取消当前 run 后重试。
- 计划到期时如果已有手动或计划 run，则本次计划记为 `deferred_busy`，不修改 `last_scheduled_run_at`，并把 `next_scheduled_run_at` 设置为 `now + min(15 分钟, interval)`。
- 手动请求遇到计划 run 时同样不启动第二轮；界面聚焦现有进度并说明可取消后重试。
- 一个 run 内每个 `site_id` 最多出现一次；结果提交仍需通过 §7.1 的 URL revision + row revision compare-and-swap。
- run 结束、取消或异常退出时必须在 `finally` 路径释放仲裁器，避免永久锁死后续检测。

## 12. JSON 与 CSV 导入导出

### 12.1 JSON

- v1 根对象固定包含 `kind: "domain-manager-export"`、`format_version: 1`、`app_version`、`exported_at`、`scope`、`categories`、`tags` 和 `sites`。
- `scope` 只能是 `all`、`filtered` 或 `selected`。
- 网站对象固定包含 §6.1 除本机并发控制字段 `url_revision`、`row_revision` 外的全部字段，并增加 `tag_ids: string[]`；可空字段使用 JSON `null`，不能用空字符串代替 NULL。分类和标签对象包含各自全部字段。
- JSON 中 `is_pinned` 使用 boolean；`failure_streak`、`sort_index`、响应码和耗时使用 integer；颜色只接受 `#RRGGBB`；其余表示与 §6 字段定义一致。
- 分类/标签对象的固定字段为 `id`、`name`、`name_key`、`color`、`sort_index`、`created_at`、`updated_at`。
- 所有 ID 必须是 UUID，所有时间必须符合 §6 的 UTC RFC 3339 格式，枚举必须使用规范中定义的英文值。
- `scope = all` 时导出全部分类和标签，包括尚未使用的项；子集导出只携带被导出网站引用的分类和标签关系闭包。
- `category_id` 和 `tag_ids` 必须引用同一文件内的定义；悬空引用在预览阶段标记为错误。
- `failure_streak` 只能是 0、1、2；`last_checked_at = null` 时自动状态必须为 `unchecked`，且检测来源、响应码、耗时、错误均为 NULL；`auto_status = available` 时必须存在 `last_success_at`。
- 导入时忽略文件中的 `normalized_url` 并按 §7 重算；不一致会在预览中警告，但以重算值为准。
- 可导出全部、当前筛选结果或选中项。
- JSON 是跨设备交换和完整字段往返的首选格式。
- 实现必须提交 `schemas/export-v1.schema.json` 并用它验证导入与测试夹具。高于当前支持版本的文件拒绝导入；低版本只有在存在显式、经过测试的迁移器时才接受。

最小合法结构示例：

```json
{
  "kind": "domain-manager-export",
  "format_version": 1,
  "app_version": "0.1.0",
  "exported_at": "2026-09-01T06:30:00.000Z",
  "scope": "selected",
  "categories": [],
  "tags": [],
  "sites": [
    {
      "id": "fe8cb38d-14f8-4d42-bfb2-f7bba0261cf6",
      "name": "Vercel",
      "domain": "vercel.com",
      "url": "https://vercel.com/",
      "normalized_url": "https://vercel.com/",
      "notes": "",
      "category_id": null,
      "tag_ids": [],
      "is_pinned": true,
      "auto_status": "unchecked",
      "manual_status": null,
      "failure_streak": 0,
      "last_checked_at": null,
      "last_success_at": null,
      "last_check_source": null,
      "last_http_status": null,
      "last_response_ms": null,
      "last_check_error": null,
      "created_at": "2026-09-01T06:30:00.000Z",
      "updated_at": "2026-09-01T06:30:00.000Z"
    }
  ]
}
```

### 12.2 CSV

- 使用 UTF-8 BOM 和标准 CSV 引号转义，便于中文 Excel 直接打开。
- `url` 是唯一必需映射的列。`name` 或 `domain` 缺失/为空时从 URL hostname 生成；其他未映射列对新增项使用默认值，对更新项保持现值。
- 标准列：`name`、`domain`、`url`、`notes`、`category`、`tags`、`auto_status`、`manual_status`、`effective_status`、`is_pinned`、`failure_streak`、`last_checked_at`、`last_success_at`、`last_check_source`、`last_http_status`、`last_response_ms`、`last_check_error`、`created_at`、`updated_at`。
- 多标签在 CSV 单元格内使用分号分隔；标签名中的反斜杠写为 `\\`，分号写为 `\;`。解析器先遵循标准 CSV 引号规则取得单元格，再按此反斜杠规则扫描标签，不能用简单字符串切分。
- 导入时自动匹配中英文常用表头，并允许手动映射。
- 导出时保护以 `=`、`+`、`-`、`@` 开头的单元格，降低表格公式注入风险。
- 具体保护规则是在以 `=`、`+`、`-`、`@`、制表符或回车开头的字符串前加一个单引号；重新导入时不自动剥离，因此 CSV 明确不是任意文本字段的无损格式。
- `effective_status` 仅用于阅读和筛选结果说明，导入时忽略；可写入的状态字段是 `auto_status` 与 `manual_status`。
- 已映射列中的空单元格表示显式清空或恢复默认：备注清空、分类变为未分类、标签替换为空集合、人工状态清除、自动状态重置为 `unchecked`；无效枚举或时间值标记为行错误。
- 空的检测时间、成功时间、来源、响应码、耗时和错误字段写为 NULL，空失败计数写为 0；非 `unchecked` 的自动状态必须同时提供合法 `last_checked_at`，`available` 还必须提供合法 `last_success_at`，否则该行无效。
- 新增项在时间列缺失时使用当前时间；更新现有项始终保留原 `id` 和 `created_at`，并把 `updated_at` 设置为提交时间。
- CSV 不承诺所有内部元数据的无损往返；需要完整迁移时使用 JSON 或备份包。

### 12.3 导入流程

1. 通过原生文件对话框选择文件。
2. 在临时数据结构中解析，不修改数据库。
3. 自动映射字段并允许调整。
4. 预览有效、重复、缺字段和格式错误的行。
5. 选择重复策略：跳过、更新现有或导入副本。
6. 用户选择取消、只导入有效行或修复后重试。
7. 使用单个数据库事务提交；任何错误完整回滚。
8. 展示新增、更新、跳过和失败数量的结果摘要。

单个文件上限为 100 MiB，网站行数上限为 100,000；超限文件在解析前或流式计数时停止，不进入预览提交。

### 12.4 重复项、字段与分类标签规则

重复匹配键是按 §7 重新计算的 `normalized_url`，不能信任导入文件提供的同名字段。

预览先以“导入开始前的数据库快照”为唯一外部匹配基准，再按 `normalized_url` 对文件内行分组；不得按文件顺序边导入边重新匹配。文件内同组超过一行时显示为独立冲突组，用户必须选择：保留其中一行并跳过其余行、把指定行作为副本分别导入，或逐行跳过。若还要更新现有网站，必须为更新操作明确选择一个源行和一个现有目标；其余源行仍需分别选择跳过或副本。最终提交使用预览生成的不可变 staging plan，因此改变文件行顺序不会改变结果。

staging plan 为每个输入 `normalized_url` 保存预览时的匹配 ID 集合，并为每个更新目标保存 `id`、`normalized_url`、`url_revision`、`row_revision`；分类/标签映射保存 `name_key` 与当时的目标 ID。提交事务开始后先重新查询并逐项比较：匹配集合、任一 revision 或名称映射发生变化时，不执行部分行，整批回滚为 `preview_stale`，要求用户重新预览。所有更新 SQL 再使用相同 revision 条件执行 compare-and-swap，影响行数不是 1 时同样整批回滚。

| 匹配数与策略 | 网站字段 | 分类与标签 | ID 与时间 |
| --- | --- | --- | --- |
| 0 条匹配 | 创建新网站 | 复用或创建导入项 | CSV 生成新 ID；JSON ID 无冲突时保留，否则生成并重映射；时间按导入值或默认值 |
| 1 条匹配 + 跳过 | 不修改 | 不为该行创建任何新分类/标签 | 不修改 |
| 1 条匹配 + 更新 | JSON 完整替换可编辑字段；CSV 只替换已映射列 | 分类替换；标签集合整体替换 | 保留现有 ID/创建时间，更新时间设为提交时间 |
| 任意匹配 + 导入副本 | 创建内容副本 | 复用或创建导入项 | 总是生成新 ID，创建/更新时间设为提交时间 |
| 多条匹配 + 更新 | 禁止隐式批量更新 | 用户必须在预览中选择一个具体目标，否则该行跳过 | 只更新所选目标 |

健康字段是 `auto_status`、`manual_status`、`failure_streak`、`last_checked_at`、`last_success_at`、`last_check_source`、`last_http_status`、`last_response_ms` 和 `last_check_error`，处理规则固定如下：

- JSON 新增：导入全部健康字段；`url_revision`、`row_revision` 在本机初始化为 1。
- JSON 更新：在规范化 URL 相同的前提下，用源对象完整替换全部健康字段；保留目标 ID、创建时间和 `url_revision`，更新时间设为提交时间，并递增 `row_revision`。
- JSON 副本：导入全部健康字段，但生成新 ID、`url_revision = 1`、`row_revision = 1`，创建/更新时间设为提交时间。
- CSV 新增或副本：已映射的健康列按输入写入，未映射列使用 `unchecked`、NULL 和 0 的默认组合。
- CSV 更新：只替换已映射的健康列，未映射列保持现值；组合结果必须继续满足 §12.1 的状态不变量，否则该行不可提交。
- 所有导入路径都重新计算 `normalized_url`。如果用户要把现有网站改成不同规范化 URL，不使用导入更新，而走 §7.1 的普通编辑与状态重置规则。

分类和标签使用“首尾去空白、Unicode NFKC、大小写折叠”得到名称匹配键：

- 同键项复用现有记录，并保留现有颜色和排序。
- 导入时重新计算 `name_key`，不信任文件中的派生值。JSON 内部 ID 先解析为文件内关系，再映射到本机复用或新建的 ID。
- 未知非空名称在提交事务中创建；无 ID 冲突时可保留合法 JSON ID，否则生成新 ID 并重映射；新颜色优先使用合法 JSON 颜色，否则使用默认色，排序追加到末尾。
- 空分类表示未分类；空标签表示空集合。
- JSON 中引用的分类/标签定义缺失属于错误，不自动猜测。
- `scope = all` 的 JSON 在确认后合并文件中的全部分类/标签，包括未使用项；子集 JSON 和 CSV 只创建最终被导入网站引用的项。
- 更新、创建分类或标签只能发生在用户确认后的同一个导入事务中；事务回滚时一并撤销。

## 13. 备份与恢复

### 13.1 完整备份包

扩展名为 `.domain-backup`。它是 ZIP 容器，包含：

- `data.sqlite3`：一致性 SQLite 快照。
- `manifest.json`：`kind`、备份格式版本 1、数据库版本、应用版本、创建时间、数据库字节数和 SHA-256 校验和。

应用设置位于 SQLite 主库中，因此不维护第二份可能与数据库冲突的设置文件。
恢复只接受这两个根级普通文件，拒绝额外条目、绝对路径、`..`、符号链接和嵌套目录。压缩包及声明的解压总大小上限为 512 MiB，实际解压字节数超过上限时立即中止。

`manifest.json` v1 结构固定为：

```json
{
  "kind": "domain-manager-backup",
  "format_version": 1,
  "schema_version": 1,
  "app_version": "0.1.0",
  "created_at": "2026-09-01T06:30:00.000Z",
  "database_file": "data.sqlite3",
  "database_size": 123456,
  "database_sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
}
```

实现必须提交对应 JSON Schema；`database_file` v1 只允许固定值 `data.sqlite3`。

备份不加密，也不包含临时文件或可重建缓存。

### 13.2 自动快照

- 数据发生变化后每日最多生成一次。
- 默认滚动保留最近 7 份。
- 保留数量可设置为 1 至 30。
- 写入应用数据目录，并使用先写临时文件再原子重命名的方式完成。
- 用户可在设置中关闭自动快照或修改保留数量。

### 13.3 恢复流程

所有数据库相关命令通过进程级 maintenance gate 协调。门控状态为 `open`、`draining`、`exclusive`：普通 CRUD、导入提交、检测结果写入、导出和自动快照只有在 `open` 时才能取得共享许可；进入 `draining` 后，新请求和正在排队但尚未取得的共享请求立即以 `maintenance` 取消，不继续等待。已经持有共享许可的短事务可以完成。网络请求本身不长期持有许可，结果提交前必须重新取得许可并校验 generation。

1. 验证容器、清单、校验和和 SQLite 完整性。
2. 备份数据库版本高于当前应用支持版本时拒绝恢复，并给出明确提示。
3. 原子地把门控从 `open` 切到 `draining`；唤醒并取消所有尚未取得共享许可的请求，拒绝新的数据库命令。
4. 暂停调度，触发活动检测队列的取消令牌。结果提交若尚未持有共享许可会立即收到 `maintenance` 并退出。
5. 等待网络任务、结果任务以及已经持有共享许可的 CRUD、导入、导出、自动快照和读写事务全部退出。
6. 在共享持有者计数为 0 后把门控切为 `exclusive`，增加数据库 generation；旧 generation 的任何迟到异步结果一律拒绝。
7. 在数据库已经静默且仍持有独占许可时创建当前数据库安全快照。
8. 关闭数据库连接并原子替换数据库，重新连接后执行允许的向前迁移。
9. 成功后重新加载调度状态和界面状态，再把门控切回 `open`。
10. 任一步骤失败时，若尚未替换数据库则保留原库；若已经替换则恢复已创建的安全快照并重新打开原库。完成回滚后才切回 `open`，此前不接受新的数据库命令或检测任务。

## 14. 错误处理与可观察性

### 14.1 错误分类

- 输入错误：在字段附近显示，保留用户输入。
- 导入行错误：在预览表逐行展示，不弹出大量通知。
- 网络错误：使用稳定错误类型和可重试操作，不暴露低层堆栈。
- 数据库错误：中止当前事务，显示数据未修改，并写入本地诊断日志。
- 文件错误：说明权限、空间、格式或版本原因，允许重新选择路径。
- vgpu 错误：静默降级到 CSS，并提供设置页诊断状态。

### 14.2 本地日志

- 使用滚动日志，仅保留排障所需事件。
- 不记录备注正文、导入数据正文、认证信息或响应正文。
- 不上传日志、遥测或使用情况。
- 设置页可打开日志所在目录，用户自行决定是否分享。

## 15. 安全与隐私

- Tauri capability 采用最小权限，前端不能任意读写文件系统。
- 所有 SQL 使用参数绑定，不拼接用户输入。
- 所有 Rust 命令重新校验输入，不信任前端或导入文件。
- 系统浏览器只允许 HTTP/HTTPS，拒绝 `file:`、`javascript:`、`data:` 和自定义协议。
- 文件恢复先验证大小、格式、版本、校验和和 SQLite 完整性。
- 网络检测的降级 GET 只读取响应头并立即丢弃响应体；任何响应正文都不持久化。
- 首版不执行导入数据中包含的任何命令、脚本或公式。

## 16. 性能目标

- 10,000 条网站记录下列表滚动保持流畅。
- 典型本机环境下关键词和组合筛选目标反馈小于 100 ms。
- 搜索输入使用短防抖，筛选与查询可取消或忽略过期结果。
- 列表使用虚拟化，只渲染可见区域。
- 检测默认并发为 5，不在界面线程执行网络或磁盘重任务。
- vgpu 在隐藏窗口时停止绘制，且不能成为核心界面的启动依赖。

这些数字是验收目标，不是对所有硬件的绝对时限；测试报告应记录使用的数据集与参考机器。

### 17.6 性能验收

- 使用固定种子的 10,000 条数据集，在 Release 构建和报告中记录的参考 macOS、Windows 机器上各运行 50 次代表性关键词 + 分类 + 多标签 + 状态查询；去掉 5 次预热后，p95 小于 100 ms。
- 使用 Playwright 驱动 5 秒连续列表滚动，记录浏览器 Performance 时间线；可见行 DOM 数保持有界，95% 动画帧间隔不高于 20 ms。

## 18. 验收标准

1. 网站、分类和标签 CRUD 完整可用且有自动化覆盖。
2. 关键词、分类、标签、状态、排序和置顶可以组合使用。
3. 批量检测、分类、标签、导出和删除操作结果正确。
4. 外部打开只接受 HTTP/HTTPS 并使用系统浏览器。
5. 手动和定时检测遵守单运行仲裁、重试、连续失败、断网保护、URL revision 和人工覆盖规则。
6. 关闭主窗口后应用在托盘继续运行，明确退出后停止。
7. JSON/CSV 导入在确认前不修改数据库，提交失败完整回滚。
8. v1 导出 Schema、备份 manifest Schema、示例和版本夹具随代码交付，并在测试中验证。
9. 完整备份可恢复；损坏、过新或恢复失败时原数据仍可用。
10. 10,000 条测试数据下满足约定的交互与查询目标。
11. WebGPU 不可用或被禁用时，所有核心功能仍可使用。
12. macOS 与 Windows 桌面冒烟测试通过。

## 19. 实施边界

本规范可以在一个实现计划中拆分为基础壳与数据库、收藏库 CRUD、搜索与批量操作、检测与托盘、数据交换、备份恢复、vgpu 视觉层和双平台验收等阶段。具体任务顺序、测试先后和提交拆分将在规范最终批准后由实施计划确定。

当前没有待定产品问题；若实现中发现会改变上述用户行为或数据格式的隐藏复杂度，应停止实施并回到设计确认。
